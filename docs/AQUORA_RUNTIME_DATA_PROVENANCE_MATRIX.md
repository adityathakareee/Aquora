## 1. Overview and Evaluation Criteria

This matrix systematically audits data provenance across all 10 user-facing modules and dashboards in AQUORA. Each view is classified by:
* **Displayed Data:** What metrics, maps, charts, or alerts are shown to the user.
* **Actual Data Source:** Exact file paths, database tables, or remote APIs providing the underlying numbers.
* **API Endpoints:** REST routes invoked between frontend and backend.
* **Computation Mode:**
  * `LIVE_DYNAMIC`: Computed in real-time by a backend solver, routing algorithm, or remote API.
  * `PRECOMPUTED_FILE_BACKED`: Stored in static JSON, CSV, GeoJSON, or Parquet files on disk and served via backend endpoints.
  * `MODEL_REGISTRY_CONTROLLED`: Dynamically dispatched to multi-tier ML model interfaces.
  * `MOCK_OR_PLACEHOLDER`: Hardcoded or generated values lacking authentic empirical backing.
* **Authenticity & Verification:** Scientific verification of the underlying raw data.
* **Governance Disclosures:** Limitations, disclaimers, and warning tags rendered in the UI.

## 3. Key Provenance Findings

1. **Phase 6 Hydrodynamic Physics Engine is 100% Live & Dynamic:**
   The deterministic physics solver ([engines/flood/solver.py](file:///c:/Users/thaka/OneDrive/Desktop/Hackathon/AQUORA/Aquoraa/engines/flood/solver.py)) is the actual, active computation engine driving the Digital Twin, Simulator, Travel Window, Critical Access, Protect the City, and Alert Center. It is NOT mock or static; it executes mass-conserving differential routing across 30m Copernicus DEM arrays on-the-fly.
2. **Machine Learning Models are NOT Running in the Live Pipeline:**
   * Phase 7E Kaggle models were never serialized to disk (notebook only).
   * Phase 7F Mahanadi models were evaluated in memory; their results are rendered via precomputed research JSON/CSV files.
   * The single trained XGBoost prototype on disk ([aquora_xgboost_prototype.joblib](file:///c:/Users/thaka/OneDrive/Desktop/Hackathon/AQUORA/Aquoraa/backend/data/models/aquora_xgboost_prototype.joblib)) degrades to `UNAVAILABLE` during cell inspection because `data/processed/phase7/landcover/landcover_class_30m.tif` is not present on disk.
   * National and Regional ML models return `is_ready: false` with `predicted_probability: null` in accordance with strict zero-fabrication rules.
3. **No Fabricated or Synthetic Predictions:**
   Where models or data files are uningested, the backend emits explicit warnings, degrades gracefully, or returns `null` rather than generating synthetic flood predictions.
